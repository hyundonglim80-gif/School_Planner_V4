# 점검 하네스 (tools/)

V4를 **실제 크롬에서 실제로 눌러 보며** 느린 곳·조용히 실패하는 곳·좁은 화면에서
어긋나는 곳을 찾는다. 선생님 실제 계정과 데이터는 건드리지 않는다. 전부
Firebase 에뮬레이터 안에서만 일어난다.

## 왜 필요했나

V4는 구글 로그인 팝업으로 막혀 있어서(`signInWithPopup`) 그냥 띄우면 로그인
화면에서 멈춘다. 그래서 자동으로는 아무것도 눌러 볼 수 없었다.
Auth 에뮬레이터를 쓰면 실제 구글 계정 없이 가짜 계정으로 들어갈 수 있고,
Firestore 에뮬레이터에 한 학년도치 가짜 데이터를 심으면 앱을 끝까지 조작할 수 있다.

## 쓰는 법

준비물은 다 갖춰져 있다. Firestore 에뮬레이터가 자바를 쓰는데,
안드로이드 스튜디오에 딸려 온 JDK 21을 그대로 쓴다.

```bash
# 1) 에뮬레이터 (창 하나를 계속 차지한다)
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"
export PATH="$JAVA_HOME/bin:$PATH"
npm run emu

# 2) 데이터 심기 (처음 한 번, 또는 되돌리고 싶을 때)
npm run seed

# 3) 앱 띄우기 — 에뮬레이터를 보게 하려면 이 환경변수가 꼭 필요하다
VITE_USE_EMULATOR=1 npm run dev:emu          # 개발 서버
# 또는 배포본 그대로 재고 싶으면
VITE_USE_EMULATOR=1 npm run build && npx vite preview --port 4173

# 4) 점검 돌리기
npm run inspect                               # 화면 돌기 — 속도/오류/모바일
npm run inspect:flows                         # 팝업 생김새 / 공유 그룹 / 내보내기
INSPECT_URL=http://localhost:4173/ npm run inspect   # 배포본 대상
```

점검은 두 갈래다.

| | inspect.mjs | inspect-flows.mjs |
|---|---|---|
| 보는 것 | 하루·주간·월간·년간·메모를 돌며 속도·오류·모바일 | 팝업 13개 생김새, 공유 그룹, 내보내기/가져오기 |

결과는 `tools/report/` 에 스크린샷과 `report.json` 으로 남는다.

## 무엇을 보나

| 보는 것 | 어떻게 |
|---|---|
| 느린 곳 | 누른 뒤 **실제로 그려질 때까지**의 시간 (rAF 두 번 기다림) |
| 화면 멈춤 | `PerformanceObserver`의 longtask — 본 스레드를 붙잡은 가장 긴 구간 |
| 조용한 실패 | 콘솔 오류, 잡히지 않은 예외, 실패한 네트워크 요청 |
| 좁은 화면에서 잘림 | 390px에서 가로로 삐져나온 요소 (가로 스크롤 영역 안은 뺀다) |
| 좁은 화면에서 겹침 | 서로 덮인 단추·입력칸 (고정 막대 밑으로 지나가는 것은 뺀다) |

## 주의할 점 — 여기서 몇 번 틀렸다

1. **시간을 재는 동작 안에 고정 대기(`waitForTimeout`)를 넣지 말 것.**
   그 대기가 그대로 '걸린 시간'으로 잡혀 숫자가 부풀어 오른다.
   첫 로드를 4.1초로 잘못 읽은 적이 있다(실제로는 1.0초).

2. **HTTP 요청 수를 'Firestore 읽기 횟수'로 세지 말 것.**
   Firestore는 연결 하나(같은 SID)를 롱폴링으로 잘게 나눠 주고받는다.
   요청이 30개라고 문서를 30번 읽은 것이 아니다. 조각 수일 뿐이다.
   제대로 세려면 앱 쪽에서 SDK 호출을 감싸야 한다. 지금은 세지 않는다.

3. **단추를 못 찾으면 조용히 넘어가게 두지 말 것.**
   모바일 하단 탭은 이름이 `📅 월간`이라 `이름이 정확히 '월간'`으로는 안 잡힌다.
   예전 하네스는 그냥 건너뛰고 같은 화면을 다섯 번 찍은 뒤 '이상 없음'이라고 했다.
   지금은 못 찾거나 화면이 안 바뀌면 그것 자체를 문제로 적는다.

4. **한 번 잰 숫자를 믿지 말 것.** 같은 단계가 0.9초에서 7.8초까지 흔들린 적이 있다.
   기계가 바쁘면 그렇다. 이상하면 다시 돌려 보고 판단할 것.

5. **겹침·넘침 검사는 정상 동작까지 잡기 쉽다.** 가로 스크롤 영역과 고정 막대는
   빼도록 해 두었다. 새 항목을 잡기 시작하면 정말 문제인지 눈으로 확인할 것.

6. **토스트는 2.5초 뒤 스스로 사라진다.** '지금 떠 있는 것'을 읽으면 늦게 읽었을 때
   조용히 실패한 것과 구별이 안 된다. 뜨는 순간을 MutationObserver로 다 기록해 둔다.
   (이걸 안 해서 멀쩡히 안내가 뜨는 곳을 '조용히 실패'라고 잘못 적을 뻔했다.)

7. **`fixed inset-0`으로 팝업 껍데기를 찾으면 배경 가림막도 같이 잡힌다.**
   마지막 것을 집으면 가림막이라 안에 팝업 상자가 없다. 검색 팝업이 그 구조여서
   '열리지 않았다'고 잘못 읽었다. 뒤에서부터 훑어 상자가 있는 것을 고른다.

8. **구글 캘린더·시트는 권한 창(새 창)을 띄운다.** 그 창을 닫아 주지 않으면 흐름이
   거기서 멈춘다. `ctx.on('page', ...)`로 받아서 닫고, 창이 떴다는 사실을 기록한다.

9. **`getByRole('combobox').first()` 같은 '첫 번째'는 쓰지 말 것.** 공유 그룹을
   하나 만들어 두면 머리말에 그룹 고르는 칸이 생겨 그쪽이 먼저 잡힌다.
   값이나 title처럼 그것만 가리키는 것으로 짚을 것.

## 여기서 찾아 고친 것

- 년간 화면(모바일)에서 '2학기' 칩 위에 날짜 이동 '◀'가 18px 올라앉아 있었다.
- 공유 그룹을 만들면 초대 코드 문서를 두 곳에서 동시에 써서 한쪽이 거부되고,
  `PERMISSION_DENIED: false for 'create' @ L55`가 그대로 화면에 떴다.
- 실패 알림에 표시가 없어 성공과 빛깔로만 구분됐다 (`❌`를 붙였다).
- 검색 팝업만 제목이 없고, 안내 문구가 잘려 있었다.
- 휴지통과 검색만 바닥에 '닫기'가 없었다.

## 운영 빌드에는 안 들어간다

`VITE_USE_EMULATOR`는 빌드할 때 상수로 치환되므로, 값이 `1`이 아니면 `src/lib/emulator.ts`
전체가 번들에서 빠진다. 평범하게 `npm run build`한 결과물에는 에뮬레이터 주소도
자동 로그인도 남지 않는다. 확인하려면:

```bash
npm run build && grep -r "9099\|connectAuthEmulator\|teacher@example.com" dist/   # 아무것도 안 나와야 한다
```
