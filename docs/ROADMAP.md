# V4 작업 순서 (로드맵)

2026-10-01 사용자와 정함. 비슷한 앱(교사용 플래너·국내 학급 도구·일반 할 일 앱)을 견주어 나온 제안을
**이 순서대로** 하나씩 한다. 중간에 멈춰도 다음 대화(다른 기기 포함)가 이 파일만 보고 이어서 할 수 있게 적는다.

## 이어서 하는 법

1. `git pull` 뒤 아래 **지금 하는 일**을 본다.
2. `git status`로 커밋하지 않은 변경이 있는지 본다. 있으면 '지금 하는 일'을 하던 것이다(그 기기에만 있다).
   다른 기기에서 이어 받으면 체크되지 않은 첫 단계부터 새로 한다.
   CLAUDE.md '지금 상태'에 `wip/…` 브랜치가 적혀 있으면 하던 단계가 거기 저장되어 있다 - `git checkout <브랜치>`로 받아 마저 하고 main에 합친다.
3. 그 항목의 **단계**에서 첫 번째 `[ ]`부터 한다. 시작하기 전에 그 기능의 사용 설명서 장과 `docs/ARCHITECTURE.md`의
   해당 장을 읽는다(CLAUDE.md 6장·ARCHITECTURE 10장 체크리스트).
4. 단계 하나를 끝낼 때마다: 단위 테스트 → 빌드 → 바뀐 부분만 크롬 확인 → 사용 설명서 → **이 파일의 체크 갱신** → 커밋·푸시.
   **main에 푸시하면 곧바로 배포된다.** 단계마다 그 자체로 완결된(배포해도 되는) 상태로만 푸시한다.
5. 항목을 끝내면 표의 상태를 `끝 (커밋)`으로 바꾸고, 다음 항목을 '지금 하는 일'로 올린다.
6. **결정 필요** 항목에 닿으면 사용자에게 묻는다. 답을 기다리는 동안은 결정이 필요 없는 다음 항목을 먼저 해도 된다.
7. 사용 설명서 전체 점검(`tools/inspect-manual.mjs`)은 항목 3개를 끝낼 때마다, 또는 사용자가 원할 때 한 번.

### 1. 일정 날짜 옮기기

- 왜: 일정은 칸을 연 날짜에 묶여 있고(설명서 '일정 추가하기'), 주간·월간에 끌기도 없다. 회의가 미뤄지면 지우고 새로 써야 해서
  알림·링크가 끊긴다. 구글 캘린더는 끌어서 옮기고, Planbook에는 날짜 옮기기·복사가 있다.
- 설계 요점
  - id는 그대로 둔다(구글 캘린더 보내기가 `sp_id`로 알아보고, 링크도 id로 잇는다). 이월처럼 새 id를 만들지 않는다.
  - 두 날짜 문서(`events/{옛 날짜}`, `events/{새 날짜}`)를 **한 트랜잭션**에서 서버로 읽고, 옛 날짜에서 그 항목만 빼고 새 날짜 끝에
    넣는다. 두 필드(`eventList`·`eventText`)는 `eventDocPayload`로 함께(ARCHITECTURE 4-1·4-4).
  - 알림(`time`, "YYYY-MM-DDTHH:mm")은 같은 날 수만큼 옮기고, 옮긴 시각이 앞으로면 `alarmTriggered`를 푼다.
    V3가 찍는 `date` 칸이 있으면 새 날짜로.
  - 이 일정에 걸린 상대 항목의 역링크는 id가 같으므로 `targetDate`만 새 날짜로 갈아끼운다.
    (`applyReverseLink`는 같은 id가 있으면 아무것도 안 바꾼다 → 같은 id의 날짜·제목을 새로 쓰는 선택지가 필요)
  - 이월 사슬(`forwardChainId`/`originalDate`)은 그대로. 이월 대상이면서 끝내지 않은 일정을 **지난 날짜**로 옮기면 다음 이월 때
    오늘로 다시 온다 → 그렇다고 안내한다.
  - 기간·반복 묶음(`groupId`)은 '이 날만' 옮겨도 묶음에 남는다(`findGroupEvents`는 모든 날짜 문서를 훑는다).
